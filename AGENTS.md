# AGENTS.md — как работать в этом репозитории

Magisk/KernelSU/APatch-модуль Android для обхода DPI: демон `nfqws2` (форк
`bol-van/zapret2`) принимает пакеты через NFQUEUE и переписывает их по
стратегиям из `strategies/*.conf`. Пользовательский интерфейс — WebUI из
`webroot/`, который вызывает `bin/nfqws2-ctl`.

Разбор файлов WebUI, правила слияния и выпуск релиза — в `CONTRIBUTING.md`.
Здесь то, что нужно агенту, чтобы не сломать трафик и тесты.

## Команды

```sh
sh tests/run.sh              # полный сьют (18 сьютов), несколько минут
sh tests/run.sh --fast       # без service/firewall и браузерных проверок
sh tests/run.sh --keep       # не удалять песочницы (путь печатается в конце)
sh tests/module/test_ctl.sh  # один сьют; их также вызывают через dash
```

* Прогон идёт на `dash` и `bash` (`NFQWS_TEST_SHELLS`), `lib/common.sh` — на
  обеих оболочках обязательно.
* `NFQWS_TEST_JOBS=1` — последовательный прогон; на машине, где каждый spawn
  стоит ~0.3 с, параллельность и есть всё время прогона.
* Браузерные сьюты (`webui: rendered geometry`) требуют node и Playwright:
  `NODE_PATH` должен указывать на `node_modules` с `playwright`, иначе сьюты
  помечаются SKIP.
* Движок не собирается локально: `bin/nfqws2` и `binaries/*` приходят из CI
  (`.github/scripts/build-android-binaries.sh`, пин zapret2 и LuaJIT там же).
  Правки shell/lua/WebUI не требуют сборки; сборка нужна только при смене пина.

## Тестовый песочник

`tests/lib/harness.sh` делает копию модуля в `/tmp/nfqws2-test.XXXXXX` и
подставляет моки вместо `iptables`, `iptables-restore`, `nfqws2`, `curl`,
`getprop`/`pm`/`sysctl`, `settings`, `rm`. Состояние iptables — реальные файлы
в `MOCK_IPT_STORE` (дренирующие циклы `while iptables -D …; do :; done` должны
заканчиваться), поэтому моки нельзя упрощать до «всегда 0».

Фикстуры через окружение: `MODDIR`/`CONFDIR`, `MOCK_IPT_STORE`,
`MOCK_IPT_FEATURES` (что «умеем» из kernel matches), `MOCK_NFQWS_FAIL`,
`MOCK_NFQWS_EBUSY`, `MOCK_IP6_FAIL`, `PROC_SYS_ROOT`, `PROC_NET_ROOT`,
`NFQWS_SYSNET`.

## Диалект shell: доказанные ловушки

Код запускается на `mksh` (Android `/system/bin/sh`) и на busybox ash. Это не
bash, и тесты на dev-машине это отличие не ловят.

* `local i="$1" pidf="…$i…"` разворачивает `$i` **до** присваивания (dash, bash
  и ash одинаково) — такие объявления разносить на две строки.
* Файлы `/proc/sys/*` отдают содержимое одним `read()`, а `read` в mksh читает
  посимвольно: вторая порция — уже EOF, значение схлопывается в первый байт.
  Парсить `awk`/`cat`/`tr` (см. `sysctl_apply`, `bench_port_base`).
* В awk нет `strtonum` (только в gawk), `length(array)` тоже; порты в
  `/proc/net/*` шестнадцатеричные — конверсия пишется вручную.
* Стиль: не писать `A && B || C` — при падении `B` выполняется `C`. Для
  `lib/common.sh` это проверяет `tests/module/test_data.sh`.
* Конвейеры внутри `nfqws2-ctl` зависают на устройстве — промежуточные
  данные кладутся в файл, и `awk` читает его аргументом.
* Файлы репозитория — LF (`.gitattributes`), правки через инструменты Windows
  (python `write_text`, `powershell > file`) приносят CRLF и ломают парсер.

## Инварианты трафика

Менять можно только с проверкой на устройстве — это счётчики пакетов и
соединения реального пользователя.

1. Ядро позволяет один слушатель на номер очереди: второй `BIND` даёт `-EBUSY`.
   Рестарт поэтому сначала останавливает службу, а не пытается поднять вторую.
2. `NFQUEUE` везде только с `--queue-bypass`: мёртвый демон должен означать
   «пропустить без изменений», а не «потерять пакет».
3. `iptables -D` не батчится в `iptables-restore`; `flush`/`delete` цепочки,
   которой нет в транзакции, валит всю транзакцию (на этом уже ломался старт с
   `ENABLE_HOTSPOT=0`).
4. «Остановлено» значит «правил нет»: `stop` проверяет `firewall_ok` и
   возвращает ошибку, если прыжки остались.
5. Живой демон ≠ работающий обход. Рестарт сверяется с трафиком: пробы до
   остановки (бейзлайн) и две после старта; если раньше открывалось, а теперь
   нет — возвращается рабочий снимок. Снимок пишется **после** вердикта, иначе
   битая конфигурация сама становится эталоном отката.
6. Порядок прыжков важен. Правила параллельного подбора стоят перед цепями
   службы; если служба переприменила правила посреди раунда, пробы меряют не
   свою стратегию — порядок проверяется по номерам строк `iptables -S` (форма
   вывода у настоящего iptables и у тестового хранилища разная, искать надо
   так, чтобы совпадало обе).
7. Повторное применение без остановки не должно плодить правила: `while -D`
   перед `-I` (пара NAT_FIX в POSTROUTING) — ровно как это делает `stop`.
8. Настроечные узлы ядра снимаются в `state/sysctls` и возвращаются при
   остановке. `nf_conntrack_tcp_timeout_established` специально не укорачивать:
   push-уведомления ходят heartbeat'ом до ~28 минут.

## Git и коммиты

* Коммиты всегда с подписью: `git commit -s`.
* Коммит — только после зелёного **полного** сьюта на этой машине; пуш —
  отдельной просьбой владельца, не «в процессе».
* Один коммит — одна причина; в тексте объясняется *почему* (репозиторий
  держит связный `git log`, по нему восстанавливают решения).
* `tools/` под git попасть не должен — `tests/run.sh` это проверяет и падает.

## Работа с телефоном (`adb`)

* Пути и кавычки: `MSYS_NO_PATHCONV=1` + `adb push` с windows-путём
  (`cygpath -w`). Вложенные `su -c "…'…'…"` распадаются ещё на уровне
  локального шелла — сложные проверки писать файлом, класть в
  `/data/local/tmp` и запускать `su -c 'sh file'`.
* Перед hot-deploy — бэкап (`tar cf /data/local/tmp/mod-orig-<ts>.tar -C
  /data/adb/modules/nfqws2-android .`), после — сверка `sha256sum` с HEAD.
* Локальные сьюты не доказывают поведение на ядре: привязка очереди,
  `--local-port` у настоящего curl, положение прыжков, `--queue-bypass` под
  нагрузкой проверяются только на устройстве.
* Системные промпты (root-запросы, LSPosed, KernelSU) — на владельце; тапать
  элементы внутри приложения и снимать замеры агент может сам, если это
  разрешено.

## Сознательно не переносим и не делаем

* `--fastpath-workaround=auto` — имеет смысл только на Keenetic.
* Фильтр клиентов хотспота по IP — отклонён владельцем.
* Закрепление DNS и hosts — удалено из модуля (`2e41b9f`), обратно не возвращать.
* Подозрение на `kill_descendants` (позиционный разбор `/proc/PID/stat` — поедет
  на `comm` с пробелом) **не подтверждено**: чинить только после проверки на
  устройстве, не «на всякий случай».
